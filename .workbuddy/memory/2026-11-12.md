## 全局规则 v2：修掉 D8036（未提交）

- 用户本机 11:45 Debug|x64 结果：v1 **失败**。三条 MSB8027 仍在，且 `cl : 命令行 error D8036: 不允许"/Fox64\Debug\%%(RelativeDir)"有多个源文件`；Core 失败，3 个 exe 显示「成功」只是增量链接了旧 Core.lib，不能算通过。
- **根因**：规则放在 `ItemDefinitionGroup`（求值阶段）。MSBuild 在求值阶段就展开 `$(...)` 属性函数，此时 `%(RelativeDir)` 仍是字面串，被 `System.String::new` 原样消费并把 `%` 转义成 `%%`；最终 `/Fo` 拿到 `x64\Debug\%%(RelativeDir)`，**不以反斜杠结尾**，cl 把它当单个输出文件名，多源文件即 D8036；同时所有 item 的 ObjectFileName 相同，MSB8027 条件仍成立。教训：**属性函数里引用 item 元数据，不能放在 ItemDefinitionGroup，必须放在 Target 内做 batching**。
- **修法**：删掉求值阶段的 ItemDefinitionGroup 块，改为文件末尾（`Microsoft.Cpp.targets` import 之后）一个自定义 Target，在 Target 内 ItemGroup 里按 item batching 设置 metadata，挂 `BeforeTargets="WarnCompileDuplicatedFilename;MakeDirsForCl;ClCompile"`（分别负责 MSB8027 判定 / 建 obj 目录 / 调 CL，见 `Microsoft.CppBuild.targets:1147,1038`、`Microsoft.CppCommon.targets:577`）：
  `<Target Name="SetUniqueObjectFileName" ...><ItemGroup><ClCompile Condition="'%(ClCompile.Identity)' != ''"><ObjectFileName>$(IntDir)$([System.String]::new('%(ClCompile.RelativeDir)').Replace('..\', ''))</ObjectFileName></ClCompile></ItemGroup></Target>`
  Condition 里的 `%()` 强制逐 item batching，属性函数此时拿到已展开的目录字符串。**同构先例**：`Microsoft.CppCommon.targets:364-377` 的 `SetCppLanguageStandardCapabilities` 用完全相同的「Target 内 ItemGroup + Condition 引用 `%(ClCompile.X)` + 属性函数里再引用 `%(ClCompile.X)`」写法，是 MSVC 每次构建都会跑的 target。
- **规则仍只有 1 条**，18 条手工配置为 0；展开模拟 36 个 ClCompile → 13 个 obj 目录，8 个 `Passive.cpp` 各占一个，同名冲突 0，所有 `/Fo` 值以 `\` 结尾（目录形式，不会再触发 D8036）。`verify_structure.py` 退出码 0；XML 合法；`git diff --check` 干净。脚本 `obj_rule_v2.py dry|apply|verify`。
