# UNOOL（UNO Online）规则

## 框架规则

游戏层次分为 **场、局、轮、回合、阶段**。

1. **场（Match）**
   - 一场游戏开始，双方进行 BP（双方各出现 10 个角色，ban 对方两个角色）。
   - 一场游戏分为数局。
   - 一名角色体力值归零时，一场结束。
   - 体力值归零的角色输，另一名角色获胜，获得积分。
   - 积分获取与角色等级有关：低等级战胜高等级时获得较多积分，反之获得少量积分。
   - **满血获胜得分翻倍**。

2. **局（Game）**
   - 一局完整的 UNO 游戏。
   - 一名角色失去所有手牌时一局结束，该玩家获胜。
   - 其他玩家扣减体力，扣减值等同于其手中剩余牌的总分值：
     - 数字牌：分值为牌面数字
     - 功能牌：20 分
     - 万能牌：50 分

3. **轮（Round）**
   - 所有角色依次进行过操作。
   - 从一号位玩家回合开始到末号位玩家回合结束视为一轮。
   - 封禁不影响回合进行。

4. **回合（Turn）**
   - 一名角色进行操作的时段。
   - 进入回合为**首个出牌阶段**，此阶段出牌后进入**结束阶段**。
   - 若未跟牌则须进行**摸牌阶段**，摸一张牌，再进行**第二个出牌阶段**：
     - 若摸牌阶段摸到的牌能打出则可打出（也可不出），随后结束回合。

5. **阶段（Phase）**
   - 在阶段内进行操作，依次为：
     - 准备阶段
     - 出牌阶段 1
     - 摸牌阶段
     - 出牌阶段 2
     - 结束阶段

## 基础规则

### 1. 牌堆构成（共 174 张牌）

| 类别 | 牌种 | 数量 | 说明 |
|------|------|------|------|
| **数字牌** | 0 | 每种颜色 2 张 | 共 4 色 × 2 = 8 张 |
| | 1~9 | 每种颜色 3 张 | 共 4 色 × 9 × 3 = 108 张 |
| **功能牌** | 封禁牌 | 每种颜色 3 张 | 共 4 色 × 3 = 12 张 |
| | 反转牌 | 每种颜色 3 张 | 共 4 色 × 3 = 12 张 |
| | +2 牌 | 每种颜色 4 张 | 共 4 色 × 4 = 16 张 |
| **万能牌** | 变色 | 10 张 | — |
| | +4 牌 | 8 张 | — |

### 2. 开局

- 每局游戏开始时**随机分配座位**。
- 每名玩家各**摸 8 张牌**。
- 根据座位号轮流进行回合。

### 3. 出牌规则

1. 若没有上一张牌，可随便出牌。
2. 否则只能打出与**当前颜色相同**或与**当前牌名相同**的牌。
3. 无论上一张牌为什么牌，均可打出**万能牌**。

### 4. 功能牌和万能牌效果

| 牌类型 | 效果 |
|--------|------|
| **反转牌** | 调转当前出牌顺序（顺时针 ↔ 逆时针） |
| **封禁牌** | 令下家跳过其下一个回合 |
| **+2 牌** | 令下家跳过其下一个回合，且其摸两张牌 |
| **万能牌（变色）** | 改变当前颜色 |
| **+4 牌** | 改变当前颜色，然后下家须选择是否质疑：<br>• **不质疑**：下家跳过其下一个回合，并摸 4 张牌<br>• **质疑且成功**（你手中有变化前公共颜色的牌）：你摸 4 张牌<br>• **质疑失败**：下家跳过其下一个回合，并摸 6 张牌 |

## 内核判定补充（Arch-C 增量，与实现对照）

以下条目与 `docs/rules.md` 正文同一事实源，按源码实现补充，供规则单测逐条对照。

### 体力与生命上限

- 角色有 `hp`（当前体力）与 `maxHp`（生命上限）。`Character::Info` 的 `hp` 为基础体力，
  `maxHp` 缺省等于 `hp`；双将合成时按双方 `maxHp` 之和的 5% 向上取整到 10 的倍数计算。
- `setMaxHp(newMaxHp)` 修改生命上限，并把当前体力压到新上限（`hp = min(hp, maxHp)`）；
  治疗同样受上限约束。部分技能（如【发射】）可据此降低上限。
- 一名角色体力归零时一场（Match）结束，另一方获胜并结算积分。

### 摸牌来源

- 普通摸牌阶段摸一张牌，从牌堆取得。
- 牌效果摸牌（如 +2 / +4 / 技能令他人摸牌）时，`Player::draw` 接收可选的 `source`
  参数，写入 `draw_begin` 触发器的 `trigger.source`，表示「使该角色摸牌的出牌者」。
  普通摸牌不带 source。技能（如【炮击】）据此区分「你因牌的效果使其他角色摸牌」的情形。
- `draw_begin` / `draw_end` 与阶段摸牌的 `phase_draw_begin` / `phase_draw_end` 是不同时机。

### 技能触发顺序

- 被动技按 `PassiveSkill::TriggerTime`  enumerated 的时机触发；同一时机按角色座次与技能注册顺序结算。
- 触发时构造 `Trigger`（player / cards / source / number），传给 `filter()` 判定、`content()` 结算。
- 子技能随父技能触发递归发动，可用 `carrier.getSkill<父技能>()` 读写父技能状态。
- 锁定技自动发动；限定技每局一次，契定技首次为可选、发动后转为锁定（每局重置）。

### 积分查表

- 胜者相对败者的积分增量由 `header/utils.h` 的 `scoreboard[胜者等级][败者等级]` 查表得到，
  等级序为 S/A/B/C/D/F：低等级战胜高等级获得更多积分，反之更少。
- 满血获胜 ×2；胜者使用增分卡再 ×2（可与满血叠加为 ×4）。
- 胜者皮肤品质加成在翻倍之后触发：精品 +1、史诗 +2、传说 +`ceil(delta*0.2)`、至尊 +5；
  败者穿戴至尊皮肤时额外 +5。饮料限定皮肤在品质加成中等同普通。
- 每种角色各有 `Level`，双将按双方等级分别查表后求和。

### 账号与商城交互（协议破坏性变更说明）

- 登录 / 注册包首字段携带协议版本（`kProtocolVersion`），服务端校验，不匹配返回可读拒绝，
  不进入业务分支。查重请求不带版本字段。
- 口令以每账号随机盐 + PBKDF2-HMAC-SHA256 派生哈希落盘，不保存明文；登录以常量时间比较校验。
  旧明文存档不兼容，需删除旧账号重新注册。
- 商城购买 / 技能描述 / 签到请求经协议层构造与解析，结果以 `std::optional<T>` 值对象回传。

### 房间与开局（协议版本 3）

- 登录成功后进入主大厅（只有「开始游戏 / 商城 / 每日签到」）；点「开始游戏」才进入房间界面
  （房间列表 + 创建 / 加入 / 刷新 / 返回大厅），匹配相关的四个消息号
  （105 / 106 / 216 / 217）已下线，编号留空不复用。客户端与服务端的版本号同时升到 3，
  旧客户端会被明确拒绝。
- 房间固定 2 人（= 一桌的两个座位），房间号由服务端生成，玩家不可指定；
  房间名由创建者给出，留空时回退为「<账号>的房间」，服务端按 64 字节上限截断。
- 开局条件：房间坐满后双方各自「准备」，两人都准备时服务端自动开局，不区分房主。
- 房主退出或掉线且未开局时，房主身份自动转让给房内另一名成员；最后一人离开后房间自动解散。
- 对局中不允许加入 / 离开：掉线成员保留座位，同账号重连会顶替回原槽位与原座位；
  对局结束后房间回到「未准备」的等待状态。
- 开局包 `GameStart` 携带本局座位号（0/1）。座位是桌面内的玩法身份，与连接槽位号无关：
  客户端据此从 `GameState` 里认出自己的手牌，`ClientInput` 里的 playerId 服务端不再采信。
  开局时**只发 `GameStart`，不补发房间快照**：客户端见到 GameStart 就切到对局界面，
  后到的 `RoomState` 会把界面按回房间页（安卓端曾因此在双方准备后停在房间页，要重连才进对局）。
  房间快照只在「准备状态变化」和「对局结束回等待」时下发；大厅列表的「对局中」标记走房间列表广播。
- 服务端并发模型：连接与 socket 由单一 IO 线程（`ServerNetwork`）独占，
  每个房间一份 `GameLogic` + 一个独立线程（`RoomGame`）；房间线程只与输入队列和出站队列交互，
  因此多房间真正并行而不会并发访问 socket。
- 同账号在另一端登录：后登录的一端顶替前一端（沿用重连顶替的槽位迁移），
  旧连接在关闭前先收到 `SessionReplaced`（221，包体只有一个原因串「你已在别处登录，本端被顶下线」），
  客户端据此提示原因并带着文案退回登录界面，而不是静默断线。掉线重连（旧连接已死）不触发该通知。
